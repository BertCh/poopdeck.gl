# STT + deck.gl Performance Evaluation (gpt-5.1-codex-max)

## Scope

- Reviewed in-repo sources for the STT format, loaders, archive reader, tileset manager, and deck.gl integration (`packages/core`, `packages/deck.gl`).
- Considered deck.gl/loaders.gl/luma.gl performance guidance (binary attributes, worker parsing, minimizing overdraw, controlling attribute updates, avoiding main-thread parsing).
- Goal: assess readiness for 120 fps “YouTube + Mapbox”-style playback with remote on-demand data.

## Architecture Snapshot

- **Format**: `.stt` = header + gzip-compressed protobuf tiles + spatial/temporal index + metadata. Columnar, quantized geom, dictionary props. Designed for HTTP range reads. (`docs/architecture/data-format.md`)
- **Archive**: Range-requests header/index/metadata; builds spatial→temporal lookup map; per-tile fetch + parse via `STTLoader`. No cache eviction yet. (`packages/core/src/archive.ts`)
- **Loader**: Always binary output; manual worker pool (max 4) with inline/bundled worker fallback; slices buffers before transfer; main-thread fallback decompress+decode. (`packages/core/src/stt-loader.ts`)
- **Tileset**: Custom manager with priority vs prefetch queues, LRU-ish eviction, 5‑minute grace, maxRequests default 64, prefetchAhead/Steps for animation. (`packages/core/src/spatiotemporal-tileset.ts`)
- **deck.gl layers**:
  - `SpatioTemporalTileLayer`: extends `TileLayer`, filters tiles by time window, but currently loads only first temporal tile per spatial index (`TODO` for multiples). (`packages/deck.gl/src/spatiotemporal-tile-layer.ts`)
  - `SpatioTemporalLayer`: composite wrapper using `SpatiotemporalTileset`, high cache limits (2 GB, 2000 tiles), aggressive prefetch by default, time ticks bypass React re-render. (`packages/deck.gl/src/spatiotemporal-layer.ts`)

## Performance Risks vs 120 fps

- **Parsing on critical path**: Worker pool limited to 4, extra `arrayBuffer.slice` copy before transfer, and main-thread fallback for any worker init failure or `disableWorker`—risks GC + stalls during playback spikes. No batching or streaming decode (`parseInBatches`) to hide latency.
- **Cache pressure/memory**: Archive tile cache has no eviction; tileset keeps 5‑minute grace + 2 GB cap—can balloon memory on long sessions or wide pans, triggering GC and dropping frames.
- **Prefetch amplification**: Tileset prefetch queries all zoom levels × steps in parallel; can flood network on fast animations or high `prefetchSteps`, and priority reservation is fixed (4) regardless of bandwidth/GPU, risking starvation or wasted bytes.
- **Temporal multiplicity**: TileLayer path loads only the first overlapping temporal tile per (z/x/y); fast playback across dense time slices will under-render or thrash if multiple tiles overlap.
- **Compression choice**: Default gzip per tile; brotli supported but not negotiated. Decompression cost (esp. on main thread) is significant relative to 8.3 ms frame budget for 120 fps.
- **GPU upload churn**: No attribute-level diffing noted; repeated tile swaps can re-upload large typed arrays each frame. Layer shaders not visible here, but large point/polygon radii will amplify fragment cost; deck.gl recommends minimizing overdraw for >60 fps.
- **Abort/cancel gaps**: Tile fetches use `AbortSignal` only in TileLayer path; tileset archive fetches lack cancellation, so rapid pans/time scrubs can keep in-flight work that is no longer needed.

## Readiness Judgment

Current stack is architected for smooth playback (prefetch, LRU, worker decode, binary features) but unbounded cache, limited worker throughput, and heavy prefetching make it unlikely to sustain 120 fps under large remote datasets without further optimization and instrumentation.

## Recommendations (priority)

1. **Tighten worker pipeline**: Remove `arrayBuffer.slice`, transfer original buffer; expose pool size option, default to `min(8, hardwareConcurrency)`; fall back to main thread only after retry; add parse time metrics.
2. **Adopt streaming/batched decode**: Use loaders.gl `parseInBatches` + transferable chunks to overlap IO/decode; consider WASM/Brotli in worker only.
3. **Cache discipline**: Implement archive-level eviction; reduce tileset grace period adaptively based on memory pressure; expose byte/entry caps and surface stats for HUD.
4. **Prefetch governance**: Cap concurrent prefetch requests, tie `prefetchAhead/Steps` to playback speed and network RTT; pause prefetch when priority queue lags; allow server hints (manifests) to avoid blind multi-zoom scans.
5. **Temporal completeness**: Load all overlapping temporal tiles per spatial index (or pick nearest by time) to avoid holes during fast scrubbing.
6. **Abort aggressively**: Wire `AbortController` through archive fetches; cancel superseded priority/prefetch requests on viewport/time changes.
7. **GPU-facing optimizations**: Keep binary attributes stable; prefer smaller radii / instanced paths; use `Model.delete()` on evicted tiles; consider deck.gl attribute transitions off for rapid scrubs; profile with luma.gl `StatsManager`.
8. **Transport tweaks**: Prefer brotli for network (smaller payloads) with worker-only decompress; consider HTTP/2 multiplexing and CDN byte-range caching; bundle tiny tiles to reduce request overhead if RTT dominates.
9. **Instrumentation & SLOs**: Add counters for decode ms, GPU upload ms, frame time, cache hit/miss, request cancel rate; gate 120 fps target by device tier (disable effects on low-end).

## Quick Wins

- Transfer buffers without copy; enlarge worker pool; enable brotli-by-default when available.
- Implement cache eviction in `STTArchive` and shorten tileset grace to <60 s with adaptive eviction.
- Cap prefetch concurrency and align prefetch window to playback speed (not fixed steps).
- Load multiple temporal tiles per spatial index to avoid under-rendering during scrubbing.
