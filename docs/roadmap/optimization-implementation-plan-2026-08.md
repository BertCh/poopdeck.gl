## How to read a work item

Every item follows one skeleton:

- **Change** — modules, functions with proposed signatures, CLI flags, schema fields. Symbols verified in the current tree are cited `file:line`; proposed ones are marked (new); anything the planning pass could not verify is marked (unverified) and must be checked before implementation.
- **Architecture** — where the piece sits, the invariants it must preserve (determinism, no-thinning, random access, bounded client memory), its byte status, and the rollback story. **BYTE-NEUTRAL** items may ship any time behind the existing gates; **BYTE-CHANGING** items ride rebuild window **R1** (one fleet republish, design doc P6) — no exceptions.
- **Tests** — enumerated unit / property / golden-fixture / simulation / integration cases, naming the existing test files to extend and the new ones to add. Every solver or encoder change carries a determinism test (byte-identical re-run); rejected-design boundaries get cheap guard tests.
- **Evaluation** — instrument, metric with units, recorded baseline where one exists, acceptance threshold, and the dataset or route to run on. **NEEDS-HARNESS** points into §1 (Phase 0), which must supply the instrument before the item's acceptance can be judged.
- **Risks & dependencies** — what invalidates the item, what it depends on, and which do-not-touch entries it borders.

Dependency spine: §1 (Phase 0) is the precondition for judging everything else; §2–§3 are the byte-neutral client program (O1); §4–§5 are the oracle/advisor upgrades (O2) that unlock the flagship (O3); §6 lands first inside Phase 4 and gates §7's rebuild window (O4); §8 is the trigger-gated spec and selection track (O5).

#### P0-3 — Deterministic client-policy trace-replay harness `§9.1–§9.5 §10.2 §11.1–§11.4 · M5/M6 acceptance instrument · Phase 0`

**Change.** The existing setup is _not_ sufficient for before/after policy comparison: frame-cost and live QoE runs are browser sessions against a real network — non-reproducible run-to-run, so a policy A/B drowns in transport noise; cold-start stops at first frame and never exercises playback policies. Since Phase 1 changes are precisely policy changes (horizon feasibility, byte-metered DRR, loop-aware eviction, decode priority), build the minimal offline replay: **record on the composite routes, replay against policy variants deterministically.**

- **Recorder:** `tools/bench/src/policy-record.mjs` (new), a frame-cost-mjs-style Playwright driver that enables `__sttProbe`, plays a route for N seconds, and dumps the P0-2 channels (`requests`, `decode`, `evict`, `playback`, plus viewport/playhead trajectory snapshots) as a JSON-lines trace to `tools/bench/out/traces/<route>-<date>.jsonl`. Routes: `severe-weather` (radar+fronts composite), `storm-4d-greenfield`, `ROUTE=/drive`.
- **Replayer:** `tools/bench/src/policy-replay.mjs` (new): `node src/policy-replay.mjs <trace.jsonl> [--archive <path-or-url>] [--variant <name>] [--json]`. Loads the real archive _directory_ through `@poopdeck.gl/core` in Node (reusing the existing `loader-hook.mjs` resolution shim the cold-start harness already registers), replays the recorded playhead/viewport trajectory against the pure policy surfaces on a mock clock, and reports: bytes fetched, request count, refetch cycles (fetch-evict-refetch of the same key), `runwayEvictions`, predicted runway violations, decode-queue wait distribution. The hook point is already right: `PrefetchPolicy` is a pure decision object — "the tileset supplies measurements and performs all the I/O the policy's answers imply; the policy itself never fetches or schedules" (spatiotemporal-tileset.ts:958–964, `packages/core/src/prefetch-policy.ts`) — and the eviction tiering and governor are plain TS classes already instantiated in Node by the vitest suites.

**Architecture.** Offline, deterministic: same trace + same policy variant ⇒ byte-identical report (integer counters, no wall clock, no RNG) — this is what makes it the arbiter for O1's "named QoE metrics move" claims. Sits beside bench in `tools/bench/src/`; consumes the archive read-only via the directory (the M5 oracle — replay cost estimates come from directory byte sums, never a size model, honoring the anti-model rejection). Reported cost is always the blended `bytes + g·reads` form — **never request count alone** (do-not-touch: the 669 MiB request-count incident, design §5). Replayed queries are the recorded client trajectory, so the rejected whole-map-instant surrogate cannot sneak back in. BYTE-NEUTRAL. Rollback: it is a tool; delete it.

**Tests.** Unit: trace parser round-trip; mock-clock monotonicity. Simulation: a hand-written 20-event micro-trace with known optimal behavior per policy (e.g. a loop-boundary trace where the current eviction demonstrably refetches — the §9.4 "inverse of Belady" pathology — asserted as the incumbent's baseline output, so the Phase 1 fix has a pinned before). Determinism: replay the committed micro-trace twice, assert byte-identical JSON output (the solver-determinism rule of P0-7 applied to this harness). Integration: record 10 s of the `earthquakes-ci.stt` fixture route locally, replay, assert conservation invariants (bytes fetched ≥ bytes decoded ≥ bytes evicted + resident). New files only: `tools/bench/src/policy-record.mjs`, `tools/bench/src/policy-replay.mjs`, `tools/bench/test/policy-replay.test.mjs`, one committed micro-trace fixture.

**Evaluation.** Self-evaluation: the determinism test above, plus one recorded trace per composite route checked into `tools/bench/out/traces/` metadata (traces themselves are local artifacts, listed not committed if large). Baseline `runwayEvictions` and refetch-cycle counts per route come out of the first recording pass — these are the NEEDS-BASELINE cells in P0-8's matrix, filled here.

**Risks & dependencies.** Depends on P0-2 (channels are the trace format). Risk: replay fidelity — the replayer models policy decisions, not GPU/render feedback; anything render-coupled (frame pacing) stays with frame-cost, and the harness must state that boundary in its header. Borders the §10.2 rejected designs and §11.4's aggregate-rate recovery formula (replay variants may not re-litigate them; the do-not-touch register is checked in review).

## 2. The client cost-oracle pass (M5)

M5 discharges defect D2 on the client: the directory prices any (cell set × time window) in exact bytes, and six controllers currently guess instead of asking. This section builds the one shared pricing utility (CO-1) and then rewires the six consumers — prefetch horizon (§9.1), governor gating (§11.1), auto-speed (§11.4), temporal-tier pick (§7.5), placeholder fetch/cover (§8.3), and range coalescing (§6.2) — onto it. All items are BYTE-NEUTRAL, ship incrementally in Phase 1 behind the existing test + browser-verify gates, and every incumbent path is retained as the fallback/kill switch; the register constraints (two-threshold gating shape, aggregate-rate recovery formula, preview-never-gates) are preserved by construction.

#### CO-1 — The shared selection-cost oracle `§9.1 §11.1 §11.4 §7.5 · M5 · Phase 1`

**Change.** The primitive exists in fragments today: every resident `DirectoryEntry` carries `length` (compressed bytes), `timeStart/timeEnd`, `temporalBucketMs?`, and `coverTMin?` (packages/core/src/directory.ts:267-300); `STTArchive.getTileByteSize(id)` resolves one tile synchronously (packages/core/src/archive.ts:2452-2454, tier-qualified via `findTileEntry`, archive.ts:2419-2442); and `SpatioTemporalTileset.estimateCost(range)` sums missing bytes — but only for the current viewport at the primary zoom, only via the async-built coverage index, and with no per-bucket breakdown (packages/core/src/spatiotemporal-tileset.ts:3283-3314). - `STTArchive.estimateSelectionCost(bounds: BoundingBox, zoom: number, timeRange: TimeRange, opts?: { bucketMs?: number; variantId?: number }): SelectionCost` (new, archive.ts), where `SelectionCost = { bytes: number; tiles: number; unknownTiles: number }` (new type). - Tileset side: extend the coverage index built in `maybeRebuildCoverageIndex` (spatiotemporal-tileset.ts:3739-3767) — which already stores per-bucket `keys[]`/`bytes[]` — with two aligned arrays computed in the same loop: `bucketByteTotals: Float64Array` and prefix sums `cumulativeBytes: Float64Array`. New methods `SpatioTemporalTileset.getByteDensityProfile(range): { bucketStarts: number[]; totalBytes: number[]; missingBytes: number[] } | null` (new) and `bytesForHorizon(time, direction, horizonSimMs): { bytes: number; exact: boolean }` (new, O(log buckets) via `lowerBound` on the prefix sums). Missing-vs-total split reuses `isCoverageReady` (spatiotemporal-tileset.ts:3106-3110) so write-offs stay excluded exactly as `estimateCost` excludes them today (:3304-3310).

This section implements mechanism M6 — the D3 repair: everywhere the client meters slots, tiles, or entries while the constrained resource is bytes, the unit of account becomes bytes; everywhere upstream priority or playhead structure is erased downstream (decode FIFO, wrap-blind eviction, recency-only caches), the information is carried through. ## 4. Measurement oracle v2 & the `--target-size` flagship (M1, M3)

This section turns `stt-optimize`'s sampled measurement (§12.1) into the universal post-zstd objective evaluator — stratified, noise-quantified, efficiency-honest attribution — points the five D4 decision sites and the advisor/doctor loops at it, and then ships the program's most user-facing move: a `--target-size B` budget solver over the reversible lever set with shadow-priced lossy proposals. Everything here is measurement- and recipe-side: no archive format bytes change, so every item is BYTE-NEUTRAL and ships in Phases 2–3 ahead of the R1 rebuild window. The do-not-touch lines it borders — `COLUMN_ZSTD_LEVEL = 19` (inspect.rs:33), the diff gate's exact directory metric (diff.rs:120-121), no analytic size models, contractual deterministic sampling, and the lexicographic no-thinning filter — are designed around, not through.

#### MO-1 — Stratified deterministic decode sampling by (zoom, time-bucket) proportional to blob bytes `§12.1 · M1 · Phase 2`

**Change.** Replace the flat systematic stride in the decode pass of `inspect` and the doctor with byte-proportional stratified sampling. Today `sample_stride` (crates/stt-optimize/src/analysis/inspect.rs:149-151) picks every `ceil(total/n)`-th directory entry, and `doctor` decodes `DOCTOR_SAMPLE_TILES = 8` the same way (crates/stt-optimize/src/doctor.rs:86); entries are sorted by the space–time curve, so a stride near the bucket count can sample one bucket phase (the aliasing risk §12.1 names). New function `stratified_sample_indices(entries: &[&DirEntry], n: usize) -> Vec<usize>` (new) in inspect.rs: group entries by `(zoom, time_start)` stratum — both fields already on every entry, exactly the stats the directory pass computes for free (inspect.rs:255-292) — allocate `n_h = n · bytes_h / bytes_total` per stratum with largest-remainder rounding (deterministic tie-break: ascending `(zoom, time_start)`), then take a stride within each stratum starting at its first entry. `inspect(tileset, sample)` (inspect.rs:251) and the doctor's `sample_decode` switch to it; `--sample 0` keeps its directory-only fast-mode semantics (the memory-recorded `inspect --sample 0` contract). `DecodeStats` (inspect.rs:69-83) gains `design: String` (new, `#[serde(default)]`, values `"stride-v1"`/`"stratified-v2"`) so a report is self-describing.

Invariants: sampling stays a pure function of the directory (no RNG, no arrival-order dependence — contractual per §12.1, inspect.rs:145-151); directory-derived stats remain exhaustive and exact; the diff gate metric (`compressed_bytes`, diff.rs:120-121) is directory-exact and is not touched by any sampling change — this item only changes which tiles feed the _per-column_ side of diff. **Tests.** Unit (extend the existing inline `mod tests` in crates/stt-optimize/src/analysis/inspect.rs and crates/stt-optimize/src/doctor.rs — both verified present): (1) allocation sums to `n` and is proportional to stratum bytes on a synthetic 3-zoom directory with skewed bytes; (2) anti-aliasing guard: a directory whose entry order interleaves k buckets with stride ≈ k gets samples from every bucket (the exact failure mode of stride-v1 — cheap guard for the rejected design); (3) `n ≥ strata count` touches every non-empty stratum; (4) `--sample 0` decodes nothing. **Risks & dependencies.** Depends on nothing; MO-2 and MO-7 consume it. Risk: very fragmented strata (thousands of buckets) make `n_h < 1` everywhere — largest-remainder rounding must still return exactly `n` indices deterministically (unit test 1 covers it). Borders the diff-gate do-not-touch entry: any refactor that routes the _directory totals_ through the sampled path is forbidden.

#### MO-3 — Leave-one-out attribution (m+1 oracle calls) `§12.1 · M1 · Phase 2`

**Change.** Replace the singleton attribution proxy with leave-one-out in both call sites. Today each column is re-encoded _alone_ (single-field IPC + zstd — `attribute_columns`, measure.rs:344-383; `ipc_zstd_len` per field, inspect.rs:232-241,340-358), which violates efficiency — the per-column sum exceeds whole-tile bytes, documented at inspect.rs:10-15 and measure.rs:90-95. New function `attribute_columns_loo(batch: &RecordBatch, zstd_level: i32) -> Result<Vec<(String, LooCost)>>` (new, shared via a small `attribution` module both files use): compute `v([m])` = zstd(IPC(all columns)) plus, for each column j, `v([m]\{j})` = zstd(IPC(batch minus column j)) — m+1 compressions, comparable cost to today's m singleton encodes. Per column publish two numbers on `ColumnCost`: `marginal_bytes: u64` (new) = `max(0, v([m]) − v([m]\{j}))` — the _actual_ post-zstd bytes the tile sheds if the column vanishes, the honest unit for doctor what-ifs — and `share` = normalized marginals (Σshare = 1, restoring the fairness axioms' efficiency property at the leave-one-out compromise §12.1 names as standard).

**Architecture.** BYTE-NEUTRAL; attribution operates on decoded Arrow batches exactly as today, so all columns — geometry, `id`, times, properties — are handled uniformly without touching the production encoder. Invariants: deterministic column order = schema order; metadata stripped before IPC exactly as the current code does to stay byte-stable (inspect.rs:341-346). **Tests.** Unit (extend measure.rs and inspect.rs inline tests): (1) efficiency: Σ marginal-derived shares = 1; (2) a duplicated column pair (perfect cross-column redundancy) gets near-zero marginals for each copy while the singleton proxy over-charged both — the misattribution case §12.1 documents; (3) a high-entropy column dominates marginals; (4) `m = 1` degenerates sanely. Determinism: byte-identical re-runs (existing sorted-descending assertions in measure.rs:441-445 extend to the new fields).

**Evaluation.** Metric: attribution error vs a sampled-Shapley reference (computable offline for m ≤ 12 columns) on three fixture datasets, LOO vs singleton — acceptance: LOO strictly closer on every dataset. Secondary: doctor projections built on `marginal_bytes` (MO-7) vs realized rebuild deltas. Uses the MO-1 harness (NEEDS-HARNESS, Phase 0).

**Risks & dependencies.** Independent of MO-1/MO-2 but shares the `ColumnCost` shape — land the serde changes together. #### WM-1 — The playback canonical query: sliding window with a buffered-runway cost term `§6.4, §6.3 · M4 · Phase 2`

**Change.** Extend `crates/stt-core/src/ordering_sim.rs` with the third canonical query the incumbent deliberately omits (ordering_sim.rs:164-166 evaluates only `scrub_hits` + `pan_hits`; the omission is patched by prose in `playback_caveat_for`, order_audit.rs:176-188). Concretely:

- `fn simulate_playback(order: &[u32], samples: &[TileSample], band: &HashSet<u64>, gap_bytes: u64, packs: &[u64], window_buckets: u64) -> PlaybackCost` (new). Semantics: the central band (`central_band`, ordering_sim.rs:343-354 — unchanged, shared integer math with spaceCurve.ts) plays a sliding window of `window_buckets` consecutive time buckets advanced one bucket at a time from `tb_min` to `tb_max`. Advance _k_ delta-fetches exactly `band × bucket τ_k` (already-buffered trailing buckets are not refetched), and — the structural difference from scrub — coalescing may not span buckets the playhead has not reached, so each advance is costed as its own per-pack coalesced read set. Implementation: one pass over the linearized order using prefix sums of blob lengths and per-bucket last-hit positions, so all per-advance costs come out in O(n + Σ hits) total, not O(n × buckets).
- `pub struct PlaybackCost { pub total: QueryCost, pub worst_advance_cost: u64 }` (new). The **buffered-runway term** is `worst_advance_cost` — the max over advances of the blended cost `bytes_k + G·reads_k`. The player must complete each advance inside one bucket of playhead time while holding a multi-window runway, so the stall proxy is the worst advance, weighted by `runway_multiplier`.
- `SimOptions` (ordering_sim.rs:70-86) gains `pub weights: QueryWeights` (new: `{ scrub: u32, pan: u32, playback: u32 }`), `pub playback_window_buckets: u64` (new, default 1), `pub runway_multiplier: u64` (new, default 4 — the production reader's 4×timeWindow prefetch runway recorded in the flow-and-riders campaign; exact reader symbol (unverified), the constant is a P1 fit target, not a law). **Default weights are `(1, 1, 0)`** so every existing pick — `--blob-ordering measured` at pack/mod.rs:946-971, `order_audit` at order_audit.rs:96-103, the layout advisor at layout.rs:143-144 — is bit-for-bit unchanged until WM-2/WM-3 turn the term on.
- `OrderingCost` (ordering_sim.rs:108-122) gains `pub playback: QueryCost` and `pub playback_worst_advance: u64`; `cost` becomes the weight-blended sum `Σ_q w_q·(bytes_q + G·reads_q) + w_playback·runway_multiplier·worst_advance_cost`. With default weights this reduces exactly to today's `total_bytes_read + total_reads*gap` (ordering_sim.rs:186).
- `OrderingCostRow` in `crates/stt-optimize/src/order_audit.rs:20-32` gains `playback_reads`, `playback_bytes`, `playback_worst_advance_cost` columns, reported **unconditionally** (even at weight 0) so the fleet re-audit in WM-3 has data before the flip; `format_text` (order_audit.rs:201-267) grows the column.

## 6. Semantic validation & manifest honesty (M7)

#### TB-1 — Pass-1 dataset statistics collection (the two-pass architecture) `§3.3 §3.4 §3.6 §3.8 · M2 · Phase 4 / R1`

**Change.** A new module `crates/stt-build/src/dataset_stats.rs` (new) providing the single pass-1 scan that every dataset-global pin consumes. Today's build already runs one whole-dataset property scan — `resolve_property_types` → `fill_property_type_gaps` (crates/spatiotemporal-tiles/src/bin/stt-build.rs:902-924, crates/stt-build/src/columnar.rs:632-648) — immediately after `source.load(...)` materializes every feature in memory (stt-build.rs:1032-1041). - `pub fn collect_dataset_stats(features: &[ParsedFeature], filter: &AttributeFilter, types: &PropertyTypes) -> DatasetStats` (new), with

Determinism: the scan is a parallel fold over ordered feature chunks with an associative merge that preserves left-chunk-first first-seen order — result independent of `--workers`. Streaming/DB inputs need no second source scan today because `source.load` fully materializes for all three backends (verified stt-build.rs:1032); the forward contract for a future true-streaming input (planned SedonaDB backend) is recorded in the module doc: either a second scan under a stable `ORDER BY` (required for first-seen order) or a bounded property-stream spill. `stt-serve` parity: the build↔serve byte-identity contract (build_options.rs:138-145) means `stt-serve` must consume identical pins — computed once per dataset at startup via one SQL aggregate (min/max/distinct per column) or loaded from `encoderPins`. Byte-break status: TB-1 alone is BYTE-NEUTRAL (it only computes); its consumers flip bytes. Rollback: `--single-pass`.

**Tests.**

Rollback story: `--no-prune` retains the previous pack fleet on R2, so rollback = re-point manifests; the previous fixture corpus is one git revert away.

**Tests.** The protocol _is_ tests, plus two additions: a CI guard that fails if any file under tests/fixtures/v2-golden changes without the marker string the regen test writes (pin changes must be self-announcing); and a `fingerprint_transform_classes` table test asserting every TB item is mapped to exactly one gate class (no item lands unclassified).

**Evaluation.** Binary: one regeneration commit for the whole window (count of pin-touching commits = 1); semantic-validate green fleet-wide; K2 warnings 0; K10 re-captured. The headline byte measurement (packed-v2-magnitude reduction on categorical-heavy datasets, bounded by the 33.6–43.9 % dictionary shares) is reported from `stt-optimize diff` old-vs-new as the window's closing record.

**Risks & dependencies.** Depends on M7 landing first (the design doc's Phase 4 makes this explicit) and on every TB item's branch discipline. The gravest failure mode is the one M7 exists for — a content-corrupting builder bug passing structural validation (the 106-archive AV precedent); the fingerprint gate, not a human with an export tool, must be what catches it. Borders the git-safety rule (large uncommitted multi-session work in-tree: targeted `git restore` only, never bulk reverts) — the regen commit must be built from a clean integration branch, not the working tree.

## 8. Declared tiers & frustum selection (M8, Phase 5)

This section covers the two Phase 5 tracks of the coherence program: **M8**, the declared-tier unification — one spec concept with a stated content contract, replacing four separately-grown tier mechanisms (exact re-bucketed temporal-LOD, additive home-zoom, reduced M4/MinMaxLTTB, the scrub tier) plus the §2.2 interval-segregation erratum candidate — and the **frustum-quadtree tile selection** (Wave 3/A1) that retires the per-tile-zoom AABB enumeration. Spec work here is design-first with trigger-gated implementation; the frustum work is BYTE-NEUTRAL client code, large but shippable outside any rebuild window. Two register entries bound everything below: bucket-keyed LOD grids never revert, and the no-thinning lexicographic partition is inviolable — reduced tiers are its sanctioned declared-variant escape, never a relaxation of it.

#### DT-1 — Unified tier-declaration spec (one concept, one review) `§1.1 §2.4 §4.5 §11.6 §13.3 · M8 · Phase 5`

**Change.** A single spec design covering every tier-shaped feature, written against the two declaration surfaces that already exist. Today's surface is split: `manifest.variants[]` registers content representations (`kind: "raw" | "summary"`, variant 0 always raw; `docs/spec/manifest.schema.json:63-86`), and `metadata.temporal_lod[]` registers coarser-bucket tiers as `TemporalLodLevel { bucket_ms, max_zoom_level }` (`crates/stt-core/src/metadata.rs:207-213`, validated by `validate_temporal_lod` at metadata.rs:513, reader pick `temporal_lod_for_zoom` at metadata.rs:387-393), with the content contract normative in `docs/spec/time-model.md` §4 ("exactly the base features, re-bucketed… no reduction, aggregation, or thinning" and the explicit promise that reduced tiers "will be announced by an explicit metadata field when specified"). The unification, concretely:

- `metadata.temporal_lod[].contract` (new, optional): `"union" | "reduced"`. Absent = `"union"` = today's normative MUST — every existing manifest stays valid and byte-identical (the writer-omission convention already used for `blobOrdering`, manifest.schema.json:92).
- `variants[].kind` enum gains `"reduced"` (new), with `variants[].method` (new: `"m4" | "minmaxlttb"`) and `variants[].params` (new, object) required when kind is `reduced`. A reduced temporal tier is then a `temporal_lod` entry whose `contract: "reduced"` names a `variant_id` of kind `reduced` — riding the existing complete address `(z,x,y,t,variant_id,temporal_bucket_ms)` (spec §3, manifest.schema.json:64) rather than inventing a new axis.
- `metadata.partition` (new, optional): absent/`"replicated"` (today) or `"home-zoom"`. When `"home-zoom"`, the manifest MUST list a new must-understand capability `"additive-partition"` in `capabilities` (registry mechanism at manifest.schema.json:55; registered in `x-stt-capability-registry`), because home-zoom changes what the _base tier at one zoom_ contains — an old parent-fallback reader would silently render a sparse slice as if complete, exactly the silent-misdecode class capabilities exist to convert into loud refusal. Reduced tiers, by contrast, need NO must-understand capability: variant 0 stays complete and readers never fetch a variant they did not ask for (the summary-tier precedent).
- The scrub tier is specified as **not a storage concept**: G5 (§11.6) is a reader _policy_ consuming whichever declared tier is byte-cheapest, resolved by DT-4. The spec text states this so the fourth "mechanism" dissolves.
- Reader negotiation rule (normative): a reader MUST NOT substitute any non-base tier for base content unless it understands the tier's declared `contract` (and `method`, if reduced). Mirrored in TS: `TemporalLodLevel` in `@poopdeck.gl/core` (consumed via `temporalLodLevels`, packages/core/src/spatiotemporal-tileset.ts:658) gains the optional `contract`/`method` fields (new).
- Conformance rules for `stt-validate` (`docs/spec/conformance.md` + crates/spatiotemporal-tiles/src/bin/stt-validate/): (1) `contract`/`method` enum-valid, method registered; (2) `contract:"union"` tiles decode to exactly the id-union of their base buckets on a deterministic sample — implementable as an M7 semantic-fingerprint comparison once Phase 4 lands; (3) `partition:"home-zoom"` ⇒ capability present, and sampled feature ids appear at exactly one zoom; (4) a `reduced` variant never shadows variant 0 (variant 0 remains addressable at every declared zoom).

**Architecture.** Spec-track, design-first (design §6 Phase 5: "one declaration mechanism reviewed once"). All fields are additive-optional; existing archives and golden fixtures are untouched, so the declaration itself is BYTE-NEUTRAL — bytes only move when DT-2/DT-3 _emit_ the new fields, under their own gates. Preserves: the formatVersion-3 variant cutover just shipped (spec §9.3 changelog — extend the registry, do not redesign the address), the time-model union MUST as the default, and conservative-superset soundness (an undeclared tier is simply never substituted). Rollback: optional fields; readers ignore what writers never emitted.

**Tests.** Unit: extend `crates/stt-core/src/metadata.rs` tests (`temporal_lod_roundtrips_through_json`, metadata.rs:890) with contract-bearing round-trips; TS mirror in `packages/core/test/manifest-schema.test.ts` (exists) — accept/reject cases for each new field. Integration: `crates/spatiotemporal-tiles/tests/validate_cli.rs` (exists) — unknown contract hard-fails, `reduced` without `method` fails, `partition:"home-zoom"` without the capability fails; `crates/stt-core/tests/spec_conformance.rs` (exists) pins the schema/spec agreement. Guard: `packages/core/test/capabilities.test.ts` (exists) — reader refuses an `additive-partition` archive it does not implement. Golden fixtures: **unchanged** — no writer emits the fields until DT-2/DT-3.

**Evaluation.** The deliverable is O5's "one reviewed tier-declaration mechanism": a reviewed spec diff plus green conformance suite; no runtime metric. Cheap fleet check: `stt-validate` over the published fleet stays green (nothing declared yet).

**Risks & dependencies.** The union-equality conformance check depends on M7's semantic fingerprints (Phase 4) — ship the declaration-time checks first, the content check second. Borders the time-model content-contract MUST (extend by declaration, never weaken the default) and the TEMPLATE/TILE_META partition (register: extend, never replace). All later DT items depend on this design being settled first — that is the point of designing once.

#### DT-5 — Interval-segregation spec erratum (draft, condition-gated) `§2.2 · M8 · Phase 5`

**Change.** A drafted erratum, produced **only if** the condition below holds — per design §6 Phase 5: "drafted only if a heavy-tailed-duration dataset shows the read-amplification in the K10-refreshed numbers." The pathology (§2.2): single start-bucket placement (`chunk_by_temporal_bucket`, crates/stt-build/src/tiler.rs:1444-1456; normative spec §3.1) plus the exact `time_end` bound means one decade-long interval makes its whole tile a permanent fetch for every later window, dragging all co-resident short features with it. Two deliverables:

- **Trigger instrumentation** (built now): `stt-optimize inspect --read-amp <window>` (new flag) — a directory-only walk (the fast `--sample 0` class) computing, from per-entry `(time_start, time_end, cover_t_min)` bounds and a sliding window, the read-amplification share `A` = expected fetched bytes attributable to tiles kept resident solely by a long-lived `time_end`, plus the residual-lifetime histogram. Deterministic, no decode.
- **The draft** (written iff triggered): relax time-model §3.1's one-tile-per-(cell, bucket) rule via a per-bucket **long-lived sibling tile**: features whose residual lifetime spans > K buckets are placed in a sibling tile at the same `(z,x,y,t)`, each tile carrying its own exact tight bounds — so the short tile's `time_end` collapses to the short features' maximum and stops pinning it. Note the precise MUST being relaxed: this keeps single placement (`|A_i| = 1`, no duplicated bytes, dedup intact) and relaxes only tile _cardinality_ per bucket — strictly weaker than the bounded-replication alternative (§2.2 Gap), which the draft proposes only as a fallback if segregation measures insufficient. Addressing/representation (a directory-visible sibling vs a DT-1 declared layout note) is the draft's central open question, to be resolved against old-reader compatibility: the reader prune predicate (spec §5; docs/spec/time-model.md:239-251) is unchanged either way — siblings simply present tighter bounds.

**Condition (spelled out).** On the K10-refreshed cold-start/playback captures, a fleet dataset with heavy-tailed interval durations (trips, storm cells — trajectories escape via boundary slicing, clip.rs:593-701 per §2.2; points/polygons do not) shows `A` ≥ a material share of playback fetch bytes (proposed 25%, fit per P1 before adoption). No number, no erratum.

**Architecture.** Drafting is paperwork; implementation, if it ever happens, is BYTE-CHANGING builder work that rides a _future_ rebuild window (P6) — explicitly not R1, which is already scoped. Preserves: exact per-tile bounds (register: within the one-bound-per-tile family the computed bounds are optimal — the draft multiplies the family, keeps exactness per member), no-thinning (placement change, zero content change), determinism (K and the split are pure functions of feature times).

**Tests.** For the instrumentation (now): unit tests on synthetic interval fixtures — one decade-long feature in a busy tile reproduces the §2.2 pathology and `--read-amp` reports it; determinism of the metric across runs; a fixed-grid-only guard (adaptive-temporal cells, §2.3, are out of scope and the flag must say so, not silently compute nonsense). No builder tests until an accepted erratum schedules implementation.

**Evaluation.** Metric: bytes-fetched-per-query-window at fixed archive size (§2.2's stated objective). Baseline: the measured `A` on trips/storm datasets post-K10. Acceptance for drafting = condition met; acceptance for the erratum = spec review. Harness: the new inspect flag; K10 capture per Phase 0/O4.

**Risks & dependencies.** Depends on the K10 re-capture (Phase 0, re-run again after R1 per Phase 4) and DT-1 (if the declared-layout representation wins). Borders the spec §8 no-duplication MUST — the reason this is an erratum, not a feature. The bucket width Δ (§2.1) scales the whole term; if M4's workload model later re-derives Δ per dataset, re-check the condition before drafting.

#### FS-1 — Frustum-quadtree cover primitive in core `§8.1 §8.2 · Wave 3/A1 · Phase 5`

**Change.** New module `packages/core/src/geo/frustum-cover.ts` (new), framework-free plain-data API (the core package carries zero deck dependency — guarded by `packages/core/test/kernel-framework-free.test.ts`; plane extraction stays in each chassis):

```ts
export interface FrustumPlane {
  normal: [number, number, number];
  distance: number;
}
export interface FrustumCoverOptions {
  minZoom: number;
  maxZoom: number;
  cameraZoom: number; // fractional
  cameraPosition: [number, number, number]; // same space as the planes
  elevationBounds?: [number, number]; // zRange / A3 altitude slab, metres
}
export function coverFrustumQuadtree(
  planes: readonly FrustumPlane[],
  opts: FrustumCoverOptions,
): TileId[] | null; // (new) — a quadtree CUT of (z,x,y) cells
```

The walk ports the shape of deck's `getOSMTileIndices` (the Wave 3/A1 record in docs/roadmap/tile-loading-3d-2026-07.md): root-down; per node, test the node's 3D Mercator AABB (dilated by `elevationBounds`) against the plane set — OUT prunes, IN/INTERSECT descends; per-branch target zoom `z_t(node) = clamp(⌊cameraZoom − log2(dist(node)/refDist)⌋, minZoom, maxZoom)`; refine while `node.z < z_t`, emit at the cut. Under the **binding bounds contract** (tile-loading-3d §4): every predicate uncertainty resolves conservative — a boundary-ambiguous plane test is INTERSECT, never OUT (under-cover is the blank-region bug class; a blank map has −∞ utility per §8.2); non-finite planes ⇒ return `null` and the caller keeps its previous selection, the exact discipline `normalizeViewportBounds` established (packages/core/src/geo/viewport-bounds.ts:102-117). Antimeridian: walk the wrapped root copy when the frustum crosses the seam and emit `x mod 2^z`, matching the archive scan's wrap-at-emit contract (`tileXSpanForLonRange`); latitude is inherently clamped by the ±85.05° tree extent (`MAX_MERCATOR_LAT`, viewport-bounds.ts:150).

**Architecture.** A pure, deterministic, output-sensitive function (O(cells emitted)); no new runtime dependency in core. BYTE-NEUTRAL — ships anytime; inert until FS-2 consumes it. This is the piece that changes §8.2's problem from "one global integer zoom" to "a per-node quadtree cut" — which is why §8.2's `(C, h)` constants must not be tuned beforehand (design §6 Phase 5: the frustum walk _subsumes_ §8.2; any tuning effort spent on the AABB stopgap is discarded when this lands). Rollback: unused export.
